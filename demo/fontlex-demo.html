Prototype · lexer-to-font compiler

Fontlex

The box below is a plain <textarea> with no highlighting code attached. The colors come from the font. Fontlex compiled a small Python lexer into OpenType substitution rules, so the browser's text shaper runs the lexer every time it draws a line.

Edit anything. Turning the font lexer off disables the font's calt feature, and the same text goes back to one color. Custom colors use CSS @font-palette-values, so retheming needs no new font.

How a font can run a lexer

1

Every character gets a copy of its glyph for each state it can be in, named like quotedbl.lx_dq_end. Copies are composites that point at the original outline, so they cost a few bytes each.

2

A chaining contextual lookup walks the text left to right. Its backtrack context sees glyphs it already replaced, so the previous glyph's copy carries the automaton's state forward. One rule per table cell:

lookup LEX {
  …
  sub @S_ident @C_digit' lookup TO_ident;
  sub @S_dq @C_dq' lookup TO_dq_end;
  sub @S_dq @C_backslash' lookup TO_dq_esc;
  sub @S_dq_esc @C_backslash' lookup TO_dq;
  sub @S_comment @C_dq' lookup TO_comment;
  …
  # fallbacks: the start state's row
  sub @C_digit' lookup TO_number;
  sub @C_dq' lookup TO_dq;
  sub @C_hash' lookup TO_comment;
  …
} LEX;
3

A second lookup recolors whole identifiers that spell a keyword. Longer words go first, and one glyph of lookahead stops is from matching inside island:

lookup WORDS {
  ignore sub @WORDLIKE @S_ident';
  …
  ignore sub \i.lx_ident' \s.lx_ident' \i.lx_ident' \n.lx_ident' \s.lx_ident' \t.lx_ident' \a.lx_ident' \n.lx_ident' \c.lx_ident' \e.lx_ident' @WORDLIKE;
  sub \i.lx_ident' lookup W_builtin \s.lx_ident' lookup W_builtin \i.lx_ident' lookup W_builtin \n.lx_ident' lookup W_builtin \s.lx_ident' lookup W_builtin \t.lx_ident' lookup W_builtin \a.lx_ident' lookup W_builtin \n.lx_ident' lookup W_builtin \c.lx_ident' lookup W_builtin \e.lx_ident' lookup W_builtin;
  …
  ignore sub \i.lx_ident' \s.lx_ident' @WORDLIKE;
  sub \i.lx_ident' lookup W_keyword \s.lx_ident' lookup W_keyword;
} WORDS;
4

Each colored copy gets a COLR record that paints the original outline with a palette entry. The font carries a light and a dark palette.

Limits of this prototype

  • State lives only within one shaping run. Browsers start a new run at each line, at a change of script (Cyrillic inside a string, for example) and wherever a fallback font takes over, so multi-line strings and some mixed-script strings lose their state.
  • Coloring is decided as each character is read, with one glyph of lookahead for words. Anything that needs longer lookahead, such as a prefix like f", needs another pass.
  • Tested in HarfBuzz and Chromium. Safari draws with Core Text, which I have not checked.
  • The base font's own ligatures are removed, because they would replace glyphs the lexer needs to see.
